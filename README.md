## Цель задания
Интеграция адаптивного веб-интерфейса интернет-магазина в полноценный веб-фреймворк Django, разделение логики проекта на модульные приложения и реализация безопасной обработки пользовательских форм.

---

## 🛠 Изменения и выполненные задачи

### Бэкенд и архитектура Django:
* **Инициализация проекта**: Развёрнута каноничная структура проекта Django внутри директории `src` с главным конфигурационным пакетом `config`.
* **Создание приложения `catalog`**: Логика интернет-магазина выделена в изолированное Django-приложение согласно архитектурным правилам фреймворка.
* **Маршрутизация (Routing)**: Настроена сквозная система адресов — глобальный `src/config/urls.py` делегирует запросы локальному роутеру приложения `src/catalog/urls.py`.
* **Реализация контроллеров (`views.py`)**: Написаны функции-представления для рендеринга всех четырёх страниц интернет-магазина (`home`, `catalog`, `orders`, `contacts`).

### Шаблонизатор и работа со статикой:
* **Интеграция Bootstrap**: Настроена папка `static/` внутри `src`, прописан путь `STATICFILES_DIRS` в конфигурационном файле `settings.py`.
* **Теги Django в HTML**: Локальные пути к стилям CSS и скриптам JavaScript во всех шаблонах переписаны с использованием тега `{% static %}`. Полностью решена проблема с кэшированием оформления.
* **Интерактивная навигация**: Ссылки в боковом меню (сайдбаре) на всех страницах адаптированы под синтаксис `{% url '...' %}`. Обеспечен сквозной переход между разделами сайта.

### [Доп. задание] Форма обратной связи и безопасность:
* **CSRF-защита**: В форму отправки сообщений на странице контактов внедрён обязательный тег безопасности `{% csrf_token %}` для предотвращения межсайтовой подделки запросов.
* **Обработка POST-запросов**: Контроллер `contacts_view` перехватывает POST-данные из полей формы, валидирует их и распечатывает лог в консоль сервера PyCharm.
* **Уведомление пользователя**: Реализован динамический вывод контекстной переменной `success` — при успешной отправке над формой отображается зелёная плашка Bootstrap Alert.

## 🧪 Инструкция для локального тестирования:
1. Убедиться, что терминал PyCharm открыт в папке `src`.
2. Запустить встроенный сервер Django командой `python manage.py runserver`.
3. Открыть в браузере адрес `http://127.0.0`.
4. Проверить переходы по кнопкам меню («Главная», «Категории», «Заказы», «Контакты») — все страницы должны открываться с полным сохранением стилей Bootstrap.
5. На странице контактов заполнить форму обратной связи и отправить её — проверить появление зелёного баннера успеха и вывод принятых данных в логах консоли.

## Этап 2: Интеграция с Django и СУБД PostgreSQL
Проект переведён на профессиональный бэкенд-фреймворк Django с подключением реляционной базы данных PostgreSQL. Реализована объектно-реляционная модель (ORM), автоматизация сиддинга данных и панель администрирования.

###  Реализованный функционал:
1. **Архитектура проекта**: Кодовая база перенесена в директорию `src/`. Создано изолированное Django-приложение `catalog` и главный конфигурационный пакет `config`.
2. **Модели данных (`models.py`)**:
   * `Category` (Наименование, описание).
   * `Product` (Наименование, описание, изображение `ImageField`, категория `ForeignKey`, точная цена `DecimalField`, даты `created_at` и `updated_at`).
   * `Contacts` (Телефон, Email, Адрес) — модель для динамического управления контактами из админки.
3. **Автоматизация наполнения БД**:
   * Написана кастомная management-команда `python manage.py fill_db`. Скрипт безопасно очищает таблицы, сбрасывает счётчики ID в PostgreSQL и заполняет базу начальными тестовыми товарами.
   * Сформированы независимые файлы фикстур в формате JSON с помощью `dumpdata` для быстрого развёртывания данных на любом компьютере.
4. **Панель администратора (`admin.py`)**:
   * Настроено детальное отображение полей (`list_display`).
   * Реализован интерактивный фильтр продуктов по категориям (`list_filter`).
   * Добавлена поисковая строка по полям `name` и `description` (`search_fields`).
5. **Динамический бэкенд**:
   * В контроллер главной страницы добавлена автоматическая выборка и вывод в консоль PyCharm последних 5 созданных продуктов.
   * Страница контактов полностью переведена на динамический вывод данных из модели `Contacts`.
   * Форма обратной связи защищена токеном безопасности `{% csrf_token %}` и корректно обрабатывает POST-запросы.

### Локальный запуск и тестирование:
1. Накатить миграции: `python manage.py migrate`
2. Запустить автоматическое наполнение тестовыми данными: `python manage.py fill_db` (или загрузить фикстуры через `loaddata`)
3. Запустить локальный сервер: `python manage.py runserver`
4. Скриншоты выполнения обязательных ORM-запросов из Django Shell находятся в корневой директории `/screenshots/`.

## Этап 3: Шаблонизация, Пагинация и Интерактивные Формы

Проект переведён на полноценную динамическую генерацию страниц с использованием встроенного шаблонизатора Django, механизмов наследования и модульных подшаблонов. Реализовано прямое управление контентом через веб-интерфейс.

### Реализованный функционал:
1. **Наследование шаблонов (DRY)**: 
   * Разработан единый базовый каркас сайта `base.html`, включающий глобальное подключение статики Bootstrap (CSS/JS) и разметку основных блоков контента.
   * Управление навигацией вынесено в изолированный подшаблон меню `src/templates/includes/inc_menu.html` и интегрирован во все разделы сайта через тег `{% include %}`. Полностью устранена проблема рассинхронизации ссылок.
2. **Динамический каталог и пагинация (Задание 2 & Доп. задание)**:
   * Выгрузка товаров на главную страницу переведена на лаконичный ORM-запрос с порционным выводом (по 3 товара на страницу) с использованием класса `Paginator`.
   * Реализован интерактивный блок навигации с кнопками «Назад», «Вперёд» и номерами страниц для переключения между списками товаров.
   * Описание продуктов в общем каталоге автоматически обрезается до 100 символов с помощью встроенного фильтра `truncatechars`.
3. **Детализация продуктов по ID (Задание 1)**:
   * Реализован бэкенд-маршрут вида `/products/<int:pk>/` и контроллер `product_detail_view` с получением первичного ключа (`pk`) и защитой от ошибок через `get_object_or_404`.
   * Разработан шаблон детальной карточки, выводящий всю информацию о товаре, включая категорию, точную цену, изображение и системные даты (`created_at`/`updated_at`).
4. **Форма создания товаров (Доп. задание)**:
   * Реализована интерактивная веб-страница `product_form.html` с валидной формой добавления новых позиций в базу данных PostgreSQL.
   * Настроена безопасная передача медиаданных (файлов изображений) через атрибут `enctype="multipart/form-data"` и обработку словаря `request.FILES`.
5. **Валидация и безопасность**:
   * Все входящие запросы к веб-формам обратной связи и создания товаров защищены от межсайтовой подделки с помощью тега `{% csrf_token %}`.
   * Добавлена бэкенд-проверка на стороне контроллеров для исключения пустых или некорректных записей.

### Локальный запуск и тестирование:
1. Запустить локальный сервер Django: `python manage.py runserver`
2. Перейти на главную страницу `http://127.0.0`. При наличии в БД более 3-х товаров снизу автоматически появится блок переключения страниц.
3. Нажать в меню «Добавить товар», заполнить обязательные поля и загрузить картинку. После нажатия кнопки «Сохранить» произойдет автоматический редирект в общий каталог с отображением новой позиции.
